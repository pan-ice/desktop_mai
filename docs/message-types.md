# MaiBot 消息结构对接

桌宠不直接解析两套内核结构。独立适配器负责经典 `maim_message`，网关插件负责 SDK 的 `MessageDict`，两者转换为桌宠 v1 的有序 `segments` 后再交给客户端。

| 内核类型                          | 经典消息结构                   | SDK 网关结构                                      | 桌宠处理                                                                 |
| --------------------------------- | ------------------------------ | ------------------------------------------------- | ------------------------------------------------------------------------ |
| `text`                            | `data` 为文字                  | `data` 为文字                                     | 显示文字，长文本按 12,000 个 UTF-16 单元拆段                             |
| `image` / `emoji`                 | `data` 为媒体 base64           | `data` 是描述，媒体在 `binary_data_base64`        | 转为内嵌图片，支持 PNG / JPEG / WebP / GIF                               |
| `voice`                           | `data` 为媒体 base64           | `data` 是描述，媒体在 `binary_data_base64`        | 按真实字节识别 MP3 / WAV / Ogg，拒绝伪装或未知格式                       |
| `at`                              | `data` 为目标 ID；兼容昵称对象 | `data` 包含 `target_user_id`、昵称和群名片        | 转为可读的 `@昵称`；只有 ID 时显示 `@对方`，不展示内部身份               |
| `reply`                           | `data` 为被引用消息 ID         | `data` 包含 `target_message_id`、原话和发送者信息 | 显示引用标记；SDK 同时保留已有的原话与发送者昵称                         |
| `seglist`                         | `data` 为消息段数组，可嵌套    | SDK 的 `raw_message` 本身就是平铺数组             | 经典模式递归展开；不将两种包络混用                                       |
| 自定义 `voiceurl`                 | 不支持                         | Host 一般包装在 `dict.data` 内                    | 网关插件读取真实音频后转换为标准音频；规则见插件协议                     |
| `file` / `forward` / 其他自定义段 | 可能出现                       | 可能出现                                          | 当前不提供对应展示和文件交付，拒绝整条回复，不发送部分内容或成功保存回执 |

SDK 媒体必须来自 `binary_data_base64`，不会将描述文字猜测为媒体；经典媒体必须来自 `data`，不会读取任意内核文件或远程 URL。经典适配器保留单媒体 9 MB、单帧 16 MiB 的限制；网关模式图片采用原有限制，单音频最多 100 MiB、单回复最多 160 MiB。每条回复最多 100 个桌宠消息段。

## 混合消息与历史

例如内核发送“文字 A → 图片 → 文字 B → 音频”，即时消息、本地保存、导出和新版服务器历史恢复都保持该顺序。桌宠的 `text` 与 `attachments` 继续保存可复用内容，新增可选 `parts` 记录文字和附件索引，避免重复存储媒体。

历史读取通过 `/account` 握手头 `X-Mai-Message-Parts: 1` 声明支持。新版中继仅对声明支持的客户端返回 `parts`；旧客户端仍获得原有格式。新版客户端也能读取旧中继和旧历史，历史原先未保存的顺序不能反推恢复。要保留新的跨设备顺序，需同时更新桌宠客户端、网关插件和中继。

## 语音自动播放

开启「自动朗读回复」或连续语音且未进入专注时，新回复中的全部音频附件按原顺序逐段播放，播完当前段后再开始下一段；后续回复继续排队。同一条消息已含音频时优先播放原音频，附带文字不重复合成；没有音频的文字回复仍使用配置的 TTS。

自动文字朗读与聊天页「朗读」只读取本次回复，跳过 `[引用消息]` 标记、引用发送者和引用原文；有分段信息时整段跳过，可包含多行引用。引用仍完整显示、保存和导出。仅含引用的文字消息不触发朗读，也不阻塞后续回复；没有分段信息的旧历史按引用标记行兼容。原音频附件继续按原样播放。

长文字按服务商限制分段。默认在当前段开始播放后预先合成下一段，最多提前一段，以减少段间等待；关闭「长回复连续播放」后恢复播完再请求。停止后不再提交后文，已提交的预合成仍可能计费。此选项不改变原音频附件的播放顺序。

关闭自动朗读且连续语音未开启、进入专注、手动打断或退出桌宠时，停止当前声音并清空所有待播片段。恢复后只播放新收到的回复，历史补载不自动播放。聊天页的每个音频控件仍可手动播放。

手动播放的聊天音频由主窗口持有，切换页面不会销毁播放器；返回聊天时同步播放位置。其他页面底部显示播放条，可暂停、继续、停止、拖动进度及前后跳转 10 秒。播放另一段会切换当前音频，清空或切换聊天历史后停止已失去归属的音频。

主窗口与桌宠共用播放归属，每次播放使用独立 ID；新播放接管旧播放，迟到的结束事件不能清除新会话。原音频与 API TTS 用 Web Audio 读取实际响度，通过独立小消息同步口型，避免每帧传输完整聊天历史；真实静音与无法采样分别处理，系统朗读采用基础动画降级。暂停、停止、专注和页面重载会释放采样与口型控制。

连续语音等待回复时保持聆听；播报期间通过回声消除、较高能量阈值和持续声音判定识别插话，停止本机当前声音并清空待播队列，后续语句仍走 ASR → MaiBot。短噪声不停止播放。录音与转写期间暂缓启动新回复的自动播报；本机停止不代表取消后端生成，也不丢弃后端稍后实际发来的回复。

发送、等待、录音、转写和播放为不同状态，不从发送成功推断内核正在生成。等待提示约 15 秒后结束，不自动重发或标记失败；晚到回复照常保存和展示。

本机 `mai-media` 协议声明媒体类型、`Content-Length` 与 `Accept-Ranges: bytes`，范围读取返回 `206` 和 `Content-Range`，无效范围返回 `416`。按所需区间流式读取，避免整段音频被误判为无限直播流而禁用进度拖动。

## 契约验证

`npm run test:message-adapter` 使用真实官方消息库和 WebSocket 服务验证经典链路。`npm run test:adapter` 额外执行 `tests/maibot-contract.integration.ts`：从本机 MaiBot 源文件加载实际组件定义和序列化方法，分别生成经典和 SDK 样本，再经过适配器与桌宠校验器，检查媒体字段、混合顺序、Unicode 拆段，以及未支持内容的完整拒绝。夹具只执行所需定义，不启动 MaiBot、不加载其模块级配置或数据库。

该契约检查需要本机 `MaiBot` 源码、独立适配器环境和网关插件环境；可用已有的 `MAI_MESSAGE_ADAPTER_PYTHON` / `MAI_PYTHON` 指定解释器。上游结构来源为 `MaiBot/src/common/data_models/message_component_data_model.py` 与 `MaiBot/src/plugin_runtime/host/message_utils.py`。

运行 `npm run build` 后，`npm run test:voice-replies` 使用隔离的实际 Electron 窗口和本机协议连接验证多段语音。仅替换浏览器声音输出以控制片段结束事件，不实际发声或请求在线 TTS；消息接收、媒体保存、React 播放队列和 IPC 使用实际实现。

`npm run test:chat-audio` 使用真实 HTML 音频和本机 90 秒静音 WAV 验证字节范围、有限时长、进度拖动、键盘跳转、跨页连续播放、底部控件、返回聊天及清空记录后的停止。媒体范围边界、HEAD、无效路径由单元测试覆盖。
