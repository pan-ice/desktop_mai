# QQ 身份、桌宠账号与设备授权

一个已验证 QQ 身份可以拥有多个桌宠账号，每个账号对应独立内核会话与聊天记录；设备凭证授权同一 QQ 名下账号的访问，账号选择必须由服务器再次核验。账号与设备都使用随机标识，客户端不接收 QQ 用户 ID 或内部人物标识。

QQ 登录命令与消息网关位于同一个桌宠适配器插件。命令只接受 Host 提供的 QQ 私聊上下文，根据真实发送者解析人物标识，向独立接入程序完成一次性登录申请。接入程序持久化账号、设备和历史，插件与客户端不直接读 MaiBot 数据库。

当前 Host 对一个网关组件只允许一个固定平台/账号/scope 组合。为保持 MaiBot 源码不变，同时让同一个 QQ 的多个账号共用人物身份且拥有独立会话，插件预声明 128 个网关槽位，由服务端为每个桌宠账号持久分配稳定槽位。内核平台采用 `desktop_pet-qq`，用户 ID 为已验证 QQ，scope 为该桌宠账号；实际会话始终由 SDK `chat.open_session` 返回。槽位独立注册、共享给该账号所有设备，不按设备反复改变网关归属。容量因此有界，扩容需同时调整槽位声明与内部协议，不允许通过客户端自行指定 scope 绕过它。

服务端 SQLite 写入成功是 QQ 账号服务器模式的回复交付边界，设备 ACK 不决定内核是否成功投递；这样全部设备离线后也能保存后续回复。消息按账号和角色去重，重复 ID 内容变化显式拒绝；未知接收状态的请求不会自动重放。原管理员凭证路径保留原有投递与连接语义，避免隐式改变已有私聊归属。
