# QQ 登录、桌宠切换与服务器聊天记录

需要桌宠客户端 0.4.0 或更新版本，并将独立 `desktop_pet_adapter` 与中继更新至 0.4.3。MaiBot 内核与 QQ 适配器源码无需改动，QQ 机器人需要已能接收私聊。公网代理需同时转发 `/desktop` 和 `/account`；`/adapter` 保持内部访问。

## 在设备上登录

1. 打开「连接与账号」，填写管理员提供的 `ws://主机:端口/desktop` 或 `wss://域名/desktop`。
2. 在「桌宠账号」填写这台设备的名称，点击「通过 QQ 登录」。
3. 用自己的 QQ 私聊对应的 MaiBot 机器人，发送界面显示的 `/桌宠登录 十位登录码`。码有效期为 5 分钟，只能确认一次。只确认自己正在使用的设备。
4. QQ 确认后，Pet 显示这个 QQ 名下的桌宠账号。选择已有账号继续聊天，或填写名称新建一个。无需用户名、密码、QQ 号或人物标识输入框。

桌宠名称用于称呼机器人；发给 MaiBot 的使用者昵称来自 QQ 授权消息。同一 QQ 切换不同桌宠时，使用者昵称不会跟着桌宠名称变化。适配器 0.4.3 修复了此前把桌宠名称当作发言者昵称的问题，并自动迁移旧数据库、保留原账号与聊天记录。更新插件及中继后重新通过 QQ 登录，再选择原桌宠即可补全昵称；无需删除或重建桌宠。尚未补全或 QQ 消息缺少昵称时使用「QQ用户」。

### IP 地址与自定义 WSS 证书

没有域名时可以填写 `wss://公网IP:端口/desktop`。如果证书由私有 CA 签发，点击服务器地址下方的「导入」，选择 CA 证书或包含完整信任链的 PEM 文件；如果服务器直接使用自签名证书，也可以导入该服务器的公开证书。支持 `.pem`、`.crt`、`.cer` 和 DER `.der`，单个文件最大 256 KiB、最多 16 张证书。包含私钥的文件会被拒绝。

证书只对导入时填写的 IP / 主机生效，端口和 `/desktop`、`/account` 路径可以共用。桌宠不会关闭 TLS 校验：证书必须在有效期内，并且 Subject Alternative Name 必须包含连接地址；例如连接 `wss://203.0.113.10:18766/desktop` 时需要 `IP:203.0.113.10`，只有 `CN=203.0.113.10` 不够。替换证书后重新导入，客户端会断开旧连接并使用新信任链重连。

服务器只向客户端提供 `.crt` / `.pem` 公钥证书。`server.key`、`.pfx`、`.p12` 等含私钥的文件必须留在服务器上。导入记录保存在客户端应用数据目录的 `server-certificates.json`，渲染页面只能看到主机、有效期和 SHA-256 指纹，不能读取证书正文。

每台设备有独立凭证，通过系统加密保存。一个 QQ 可以创建多个桌宠账号，账号之间的会话和聊天记录分开。同一个账号可同时连接多台设备，发言和回复实时同步；切换只影响当前设备，不会把其他设备踢下线。

展开「设备管理」可以移除旧电脑或退出当前设备。撤销后该设备的连接立即断开、凭证失效，其他设备继续使用；撤销不删除服务器账号和历史。重新使用该设备时再次通过 QQ 验证。

桌宠账号旁的「移除」仅将它从这台电脑的列表移除，并保留服务器账号、全部聊天记录和本机缓存。移除当前桌宠会断开本机连接，其他设备继续聊天；移除其他桌宠不影响当前连接。本机移除偏好在重启后保留，可展开「添加已有桌宠」重新添加并连接，继续使用原有聊天记录。该操作与撤销设备授权、清空聊天记录分别独立。

## 本机测试自动初始化

在「连接与账号」展开「本机测试」，点击「本机测试（自动初始化）」。已知本机安装目录会直接复用，未配置时只需通过文件夹选择器选择一次 MaiBot 目录。桌面端会填入 `ws://127.0.0.1:18766/desktop`，自动准备 `data/desktop-server/server.json`、配套的插件 `config.toml`，并在后台启动中继。已准备过时也可以直接填写本机 `ws://127.0.0.1:端口/desktop`，点击「通过 QQ 登录」，按需启动中继。

MaiBot 目录应已安装新版桌宠适配器及依赖。初始化会复用已有内部令牌、账号、数据库和历史；更改插件配置前保留原文件备份，不覆盖其他远程中继配置。若此前用命令初始化过，可以从同目录的 `adapter.generated.toml` 恢复配套令牌；不匹配时明确报错，不轮换令牌或重置数据。

MaiBot 在桌宠之外独立运行；首次准备完成后，在 MaiBot 中重载一次桌宠插件以应用配置，再通过 QQ 私聊确认登录码。MaiBot 的协议确认、模型配置与 QQ 接入按 MaiBot 自身流程完成，客户端不提供内核启动或停止。`18766` 默认提供普通 WebSocket；本机、局域网或其他受信网络可直接使用 `ws`，公网建议使用带有效证书的 `wss`。

桌面端只关闭自己启动的中继，退出桌宠或切换到其他服务器时自动回收；已经由终端或系统服务启动的中继只复用，不接管其生命周期。自动准备产生的账号与聊天记录保存在所选 MaiBot 的 `data/desktop-server/server.sqlite3`，退出或重启后保留。

## 聊天记录保存在哪里

接入程序将账号归属、设备凭证摘要、聊天文字及已发送图像/语音附件保存到 `server.json` 同目录的 `server.sqlite3`。它就是部署方自己的服务器存储，不要求接入其他云服务。QQ 号与内部 `person_id` 仅用于服务端归属，不写进客户端账号列表、握手身份或本地设置。

新设备连接账号时加载最近一页记录，可在聊天页「加载更早的聊天记录」。新消息同步到同账号的在线设备；设备全部离线时，适配器仍可将该账号已产生的内核回复持久化，之后登录可查看。服务端记录不随断线、插件重载或进程重启消失。本机缓存最多保存最近 1000 条，云端分页记录保留到用户清空。

清空聊天记录需再次点击确认，会清空所选桌宠账号的服务器记录并通知在线设备，其他桌宠不受影响。MaiBot 自身的会话数据库与长期记忆由内核管理，这个操作不会删除它们。同一个 QQ 的人物画像按内核的人物归属规则共享，不等于各桌宠拥有独立人格或工具权限。

服务器数据库含对话与附件，应与部署数据一起备份并限制访问；它不包含未发送的本机屏幕、模型资源或设备上的声音设置。运行期间备份应使用 SQLite 的在线备份接口；也可以停止接入程序后备份数据库及其 WAL 文件，不要在写入时只复制主数据库。

## 本地验证与预览

```powershell
npm run build
npm run test:qq-login
npm run test:local-server
```

脚本启动隔离的实际 Electron 应用、真实插件和 SDK，用测试 Host 模拟 QQ 命令上下文及模型回复。覆盖 QQ 登录、新建与切换桌宠、三份独立客户端、从服务器恢复历史、实时同步、撤销设备和分账号清空；结束时回收进程。截图位于 `.cache/qq-login-smoke/`。此验收不发送真实 QQ 消息，也不调用在线模型。
