# Mai · 桌面伙伴

以 **MaiBot 为对话内核**、参考 [N.E.K.O](https://github.com/Project-N-E-K-O/N.E.K.O) 桌面陪伴体验开发的 Windows / macOS 桌宠。Electron + React + TypeScript；不附带第三方角色模型，可导入自己的角色。

桌宠可通过本仓库 `adapter/` 内的**独立 Python 适配器**接入 MaiBot 官方经典消息服务，按官方 `maim_message` 协议收发私聊。人格、回复策略、表达学习、长期记忆、插件与工具由 MaiBot 负责。原 MessageGateway 网关插件和 QQ 服务器接入继续保留；主动陪伴需要网关插件提供的任务接口。

桌宠客户端与独立适配器在 [desktop_mai](https://github.com/pan-ice/desktop_mai) 以 [MIT 许可证](LICENSE) 开源。直接使用请下载发行包；开发与打包见[从源码运行与打包](#从源码运行与打包)。

MaiBot 由部署方独立安装，客户端仓库不包含 `MaiBot/`。仅在需要原 QQ 服务器、云端历史或主动陪伴时，另行获取原[网关插件仓库](https://github.com/pan-ice/desktop_pet_adapter)，放入 `MaiBot/plugins/desktop_pet_adapter`。

![陪伴空间预览](docs/preview.png)

使用顺序：[下载安装](#下载安装) → [连接 MaiBot](#首次使用与配置) → [配置角色](#配置角色) → [配置声音](#配置声音) → [录音与连续语音](#录音与连续语音)。遇到问题先看[配置排错](#配置排错)。

## 下载安装

直接使用请前往 [GitHub Releases](https://github.com/pan-ice/desktop_mai/releases/latest) 下载，无需安装 Node.js：

| 系统                        | 文件                                     | 使用方式                             |
| --------------------------- | ---------------------------------------- | ------------------------------------ |
| Windows x64 安装版（推荐）  | `Mai-Desktop-Pet-版本-win-x64-Setup.exe` | 安装向导，可选目录，含快捷方式和卸载 |
| Windows x64 便携版          | `Mai-Desktop-Pet-版本-win-x64.exe`       | 无需安装，直接运行                   |
| Mac Apple Silicon（M 系列） | `Mai-Desktop-Pet-版本-mac-arm64.dmg`     | 打开后拖入 Applications              |
| Mac Intel                   | `Mai-Desktop-Pet-版本-mac-x64.dmg`       | 打开后拖入 Applications              |

Mac 另提供 ZIP，解压后将 `.app` 移入 Applications。Mac 包使用 ad-hoc 签名，尚无 Apple Developer ID 签名或公证；首次打开若被系统拦截，可在“系统设置 → 隐私与安全性”中允许打开。Windows 包也未使用商业代码签名。每个 Release 附带 `SHA256SUMS.txt` 与独立适配器 ZIP。

Windows 安装版默认安装到当前用户，可选择安装目录，创建桌面和开始菜单快捷方式；卸载入口位于系统“已安装的应用”。默认保留个人设置和聊天数据。此前使用便携版的用户可以改用安装版。

## 首次使用与配置

先接通文字聊天，再按需开启角色、朗读、麦克风和屏幕分享。安装包提供桌宠客户端，**聊天需要已经配置好模型服务的 MaiBot，或管理员提供的桌宠服务器**。没有连接内核时，可以先调整外观和测试声音，但不会生成聊天回复。

### 1. 确认配置填在哪里

| 要配置的内容                           | 填写位置                                                                 | 用途                                                  |
| -------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------- |
| 聊天、视觉模型的地址、模型名和 API Key | **MaiBot 的管理界面或模型配置**；使用他人服务器时由管理员配置            | 生成回复、理解图片；桌宠没有单独的聊天模型 Key 输入框 |
| 朗读服务的 API Key                     | 桌宠「声音与感知」→「音色服务」下方，或「高级声音设置」→「合成 API Key」 | 文字转语音，每家服务商分别保存                        |
| 录音识别的地址、模型和 API Key         | 桌宠「声音与感知」→「录音与转写」                                        | 把麦克风声音转成文字，与朗读分别配置                  |
| MaiBot 消息服务令牌                    | MaiBot 的 `[maim_message].auth_token`，以及独立适配器的 `[maibot].token` | 连接内核，两处填写相同的令牌原文                      |
| 桌宠接入令牌                           | 导出的适配器配置 `[desktop].token`，由桌宠自动填写                       | 适配器连接桌宠；保留导出的值                          |

连接令牌、模型 API Key 和 QQ 登录码用途不同，不要互相替换。输入 API Key 后需要点击对应的保存按钮；已保存的密钥不会在输入框中回显，界面会显示已保存状态。

### 2. 选择一条连接路线

| 你的情况                                       | 使用路线                                    | 需要准备                                          |
| ---------------------------------------------- | ------------------------------------------- | ------------------------------------------------- |
| 管理员已经提供桌宠服务器                       | [方式 A：服务器与 QQ 登录](#connect-server) | 完整的服务器地址，以及能私聊该服务器 MaiBot 的 QQ |
| 自己部署 MaiBot，主要使用本机聊天              | [方式 B：独立适配器](#connect-local)        | 已配置模型的 MaiBot、Python 3.11+、独立适配器 ZIP |
| 已经部署原网关插件，或需要它提供的主动陪伴能力 | [原插件接入](#原插件接入兼容)               | 配套的网关插件与部署环境                          |

<a id="connect-server"></a>

#### 方式 A：连接现成的桌宠服务器

1. 向管理员取得完整地址，例如 `wss://你的服务器域名/desktop`。这是桌宠服务器地址，包含 `/desktop` 路径；MaiBot 网页管理地址不能填在这里。
2. 打开桌宠左侧「连接与账号」，填写服务器地址，点击「保存地址」。若管理员使用自签名或私有 CA 证书，按[多人服务器说明](#多人服务器)导入其提供的公钥证书。
3. 在同页「桌宠账号」点击「通过 QQ 登录」。用自己的 QQ **私聊这台服务器的 MaiBot**，发送页面显示的 `/桌宠登录 登录码`。登录码有效期为 5 分钟。
4. 验证成功后，选择已有桌宠账号，或填写名字并点击「新建桌宠并连接」。换电脑时选择已有账号可以恢复该服务器上的聊天记录。
5. 等页面显示已连接，再打开「和麦麦聊聊」，发送“你好”确认回复。只完成 QQ 验证后仍需选择一个桌宠账号。

这条路线不需要在你的电脑上安装 Python 或运行独立适配器。模型文件、朗读音色和语音 Key 仍需在每台电脑上配置。

<a id="connect-local"></a>
<a id="官方消息协议接入"></a>

#### 方式 B：用独立适配器连接自己的 MaiBot

下面以 **MaiBot、适配器和桌宠都在同一台电脑** 为例。容器或远程部署请参照[独立适配器说明](adapter/README.md#启动适配器)调整地址与网络。

1. 按 [MaiBot 官方文档](https://docs.mai-mai.org/)部署并启动内核，在它的管理界面配置聊天模型的服务地址、模型名、API Key 和人格；需要图片理解时同时配置视觉模型。桌宠不会代为安装或启动 MaiBot。
2. 从 [Releases](https://github.com/pan-ice/desktop_mai/releases/latest) 下载 `MaiBot-Desktop-Message-Adapter-版本.zip`，解压到独立目录。源码用户可直接使用本仓库 `adapter/`。准备 Python **3.11+** 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)；该 ZIP 是独立程序，不放进 `MaiBot/plugins`。
3. 编辑 MaiBot 的 `config/bot_config.toml`：在现有 `[bot].platforms` 列表中**追加** `"desktop_pet:mai_desktop_pet"`，并在现有 `[maim_message]` 中配置经典消息服务和令牌，然后重启 MaiBot。以下是相关字段示例，应合并到现有配置，保留其他平台与令牌，不要重复添加同名配置节。

   ```toml
   [bot]
   # 示例仅列桌宠这一项，实际应保留原列表中的 QQ 等其他平台。
   platforms = ["desktop_pet:mai_desktop_pet"]

   [maim_message]
   ws_server_host = "127.0.0.1"
   ws_server_port = 8000
   auth_token = ["替换成自己生成的一段足够长的随机令牌"]
   ```

4. 打开桌宠「连接与账号」→「独立适配器接入」。首次使用可将「桌宠接入端口」留空，点击「导出配置并开启接入」，将文件保存为适配器目录中的 `config.toml`。桌宠会分配实际端口、生成令牌并开启监听。
5. 打开刚导出的 `config.toml`，只修改 `[maibot]` 中的连接信息。`token` 填上一步 MaiBot `auth_token` 列表中的一个值，**不要加 `Bearer ` 前缀**。保留 `[desktop]` 的地址和令牌以及 `[identity]` 的默认身份。

   ```toml
   [maibot]
   url = "ws://127.0.0.1:8000/ws"
   token = "与 MaiBot auth_token 中的一个值完全相同"
   ```

6. 在包含 `pyproject.toml` 和 `config.toml` 的适配器目录打开终端，执行以下命令。Windows PowerShell 与 macOS 终端使用相同命令：

   ```sh
   uv sync --locked
   uv run --locked python -m desktop_adapter --config config.toml --check-config
   uv run --locked python -m desktop_adapter --config config.toml
   ```

7. 保持 MaiBot 和适配器进程运行。桌宠显示「MaiBot 消息服务已连接」后，在「和麦麦聊聊」发送“你好”，确认收到回复。以后启动时仍需运行这三个程序；桌宠断开后可在「独立适配器接入」点击「开启接入」。

如果 MaiBot 配置了适配器访问策略，需要放行默认私聊身份 `desktop_owner`，具体见[访问策略示例](adapter/README.md#访问策略)。同一平台只运行一个经典适配器；原桌宠网关若占用相同平台，需要先停用。改变桌宠端口或身份后，重新导出配置，补回 MaiBot 地址和令牌并重启适配器。

本模式支持文字、图片与语音回复；QQ 登录、服务器历史同步及主动陪伴需要服务器或网关路线。适配器固定使用 `maim-message==0.6.8`，不要自行替换为协议已变更的 0.7 开发版。完整配置、pip 启动方式和媒体限制见[适配器说明](adapter/README.md)，协议依据见[参考笔记](docs/adapter-protocol-reference.md)。

<a id="配置角色"></a>

### 3. 选择角色与称呼

1. 默认占位角色可以直接使用。想换角色时，打开「角色衣橱」→「导入角色」，选择图片或模型入口文件；已有完整模型目录可选「导入模型文件夹」。ZIP 先解压，Live2D 要保留贴图等配套资源。
2. 导入后点击角色卡片的「使用」，再点击顶部「召回桌宠」查看桌面效果。支持格式和 Live2D 运行库准备方式见[角色资源](#角色资源)。
3. 到「偏好设置」修改「你的名字」和「桌宠的名字」，点击「保存称呼」；希望自动采用内核名字时开启「跟随 MaiBot 名称」。名字只改变桌宠的称呼，内核人格仍在 MaiBot 中设置。
4. 按需调整角色大小、始终置顶和锁定位置。开启「鼠标穿透」后，在偏好设置或托盘菜单关闭即可恢复点击，也可以使用页面显示的恢复组合键。

<a id="配置声音"></a>

### 4. 配置回复朗读

入口是「声音与感知」→「让麦麦的声音陪着你」。朗读用于把 MaiBot 的文字回复转成声音；录音识别在下一步单独配置。

**先试系统声音：** 展开「高级声音设置」，将「朗读方式」选为「系统语音 · 无需 API」，选择系统声音，点击「保存声音设置」后「试听声音」。满意后开启「自动朗读回复」。这条路线无需语音服务 Key；可用声音取决于操作系统安装的语音包。

**使用在线服务的预置音色或兼容接口：** 在「高级声音设置」选择「模型语音 · 在线服务」和对应「语音服务商」，填写「合成服务地址」「合成 API Key」「语音合成模型」及「音色 ID」或「朗读音色」。服务地址填 API 根路径，保留 `/v1` 等前缀，不填控制台网页或重复追加 `/audio/speech`。点击「保存声音设置」→「试听声音」，确认后开启「自动朗读回复」。兼容 OpenAI 的合成服务选择「兼容语音 API」；只有服务端允许无鉴权时，Key 才可留空。

**使用自己准备的声音：** 页面顶部「音色服务」选择服务商，在其下方填写对应 API Key 并点击「保存 Key」，再按下表操作。这个输入框保存后仍会保留；更换密钥时填写新值并点击「更新 Key」。

| 服务商     | 音色配置流程                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------- |
| 小米 MiMo  | 点击「导入音色音频」选择 MP3 / WAV，参考音频保存在本机，合成时随请求发送；准备成功后自动选用      |
| 硅基流动   | 导入 MP3 / WAV，客户端自动识别参考原文并上传；识别失败时在「补充选项」填写原文后重试              |
| MiniMax    | 导入支持格式的参考录音，客户端自动准备音色 ID；文件格式、大小和时长以页面提示为准                 |
| 阿里云百炼 | 导入 MP3 / WAV，等待音色就绪；保留客户端为该音色匹配的合成模型，地址与 Key 使用同一地域或业务空间 |
| 火山引擎   | 先在火山官方控制台上传并完成复刻，再回桌宠填写 API Key 和已有音色 ID，详见下面步骤                |

前四家的简单导入在准备成功后会选用音色并开启自动朗读；可用「试听声音」确认效果。试听、在线朗读及部分音色准备操作会调用服务商接口，具体额度和费用在对应控制台确认。完整的材料要求、预置音色、进阶选项和调用说明见[声音配置指南](docs/voice-cloning.md)。

**火山引擎已有复刻音色的配置顺序：**

1. 在顶部「音色服务」选择「火山引擎」，点击「打开火山上传指引」，到官方控制台自行上传、完成复刻并确认音色效果。
2. 回到桌宠，在「火山引擎 API Key」填写音色所属项目的**豆包语音新版 API Key**，点击「保存 Key」。此处使用 `X-Api-Key` 鉴权，不填 AccessKey、SecretKey 或旧版 Access Token。
3. 在「已有火山音色 ID」填写控制台返回的 ID，例如 `S_` 开头的复刻音色槽位，点击「保存火山音色」。这一步只保存配置，不上传音频、不创建音色，且会保持自动朗读关闭。
4. 如需核对，在「高级声音设置」查看：本客户端默认合成地址为 `https://openspeech.bytedance.com/api/v3/tts`，模型为 `seed-tts-2.0-standard`；上述复刻音色入口会将「语音资源 ID」设为 `seed-icl-2.0`。使用系统预置音色时则在高级设置中选择对应音色和资源，默认资源为 `seed-tts-2.0`。
5. 在服务商控制台确认音色已可用及相关收费规则后，再点击「试听声音」。试听会发起正式合成请求，可能涉及合成或音色费用；确认后自行开启「自动朗读回复」。仅保存 Key 和音色 ID 不会发起合成。

<a id="录音与连续语音"></a>

### 5. 配置录音转写与连续语音

1. 在「声音与感知」→「录音与转写」填写支持 OpenAI 转写协议的「API Base URL」「转写 API Key」「转写模型」。Base URL 保留 `/v1` 等前缀；模型填写服务商提供的识别模型，不能把聊天模型或朗读音色 ID 填在这里。
2. 点击「保存转写设置」。本地无鉴权服务可以不填 Key；其他情况按服务商要求填写。配置朗读服务不会自动替你配置转写。
3. 在「麦克风试一试」点击录音，说一句话后再点一次结束；首次使用时允许系统麦克风权限。出现正确的转写文字即说明识别链路正常，**这里的测试不会自动发送聊天消息**。
4. 确认文字聊天已接通、桌宠可见，再开启「连续语音对话」。说话后停顿，录音会先转成文字并发给 MaiBot；需要听到回复时再开启前一步的「自动朗读回复」。可通过「停顿多久后发送」调整节奏，修改后点击「保存语音节奏」。

连续语音的流程为「麦克风 → 转写服务 → MaiBot → 朗读服务」，各部分分别使用自己的配置。断开连接、隐藏桌宠或进入专注模式会停止连续语音；重新使用时需要再次开启。转写测试与连续语音会使用所配置服务的额度。

### 6. 按需开启屏幕、摄像头和主动陪伴

- **屏幕分享：** 在「声音与感知」开启「屏幕感知」，点击「选择屏幕或窗口」，预览截图并确认后分享给 MaiBot。内核需配置可用的视觉模型；系统提示时授予屏幕录制权限。
- **自动屏幕陪伴：** 先选择目标窗口，再开启独立的「自动屏幕陪伴」开关；调整观察间隔后点击「保存屏幕节奏」。它会持续按间隔分享有变化的画面，断线、专注、免打扰或隐藏桌宠时暂停。
- **摄像头：** 点击「打开摄像头」，允许摄像头权限，拍摄并预览后再发送；关闭预览即停止使用摄像头。
- **主动陪伴：** 使用支持任务接口的原网关或服务器模式时，在「主动来找你」开启「主动陪伴」，调整搭话间隔与免打扰时段并点击「保存陪伴节奏」。独立适配器模式下该开关不可用。

### 7. 日常启动与数据保存

文字与声音都正常后，可在「偏好设置」开启「启动时自动连接 MaiBot」和「开机启动」。自己部署的 MaiBot、独立适配器仍需保持运行。设置页有保存按钮的表单需要提交后才生效。

关闭控制面板后应用会保留托盘，点击「召回桌宠」或托盘入口可重新显示；完全退出请用托盘菜单「退出 Mai」。设置、模型和声音配置保存在本机，可通过「偏好设置」→「应用数据目录」→「打开目录」查看。服务器路线的聊天记录随账号同步；本机路线保存在本机。卸载安装版默认保留个人数据。

## 配置排错

先点击右上角铃铛「运行动态」查看具体提示；自己部署时同时检查 MaiBot 与适配器终端。

| 现象                         | 检查顺序                                                                                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |

## 多人服务器

0.4.0 支持 QQ 验证登录：一个 QQ 可以创建多个独立桌宠账号，每个账号可以由多台设备同时使用。新设备通过 QQ 私聊机器人确认登录码后，选择已有桌宠即可恢复服务器聊天记录，也可以新建一个桌宠。人物标识只保留在服务端，不由用户填写或传给客户端。

用户打开「连接与账号」，填写服务器地址，点击「通过 QQ 登录」，用自己的 QQ 私聊 MaiBot 发送显示的 `/桌宠登录 登录码`。确认后选择或新建桌宠；设备管理按需展开。聊天记录及已发送附件保存在同一台服务器的 SQLite 数据库，支持跨设备同步、分页加载和分账号清空，无需第三方云服务。模型文件和声音设置仍保存在本机。旧管理员凭证可在「旧版接入」中导入，原有账号和聊天记录继续保留。

操作与预览验证见 [QQ 登录说明](docs/qq-login.md)。自行部署原服务器时，需取得[原网关插件仓库](https://github.com/pan-ice/desktop_pet_adapter)的访问权限，并参照其中的 `SERVER.md` 配置服务、Caddy 或 systemd；使用管理员提供的服务器时无需自行部署。

本机测试需要先在本机 MaiBot 中安装原网关插件及其 Python 依赖，再点击「本机测试（自动初始化）」，选择该 MaiBot 目录。桌宠会准备配套配置并启动中继，然后在 MaiBot 中启动或重载插件、通过 QQ 登录。默认地址为 `ws://127.0.0.1:18766/desktop`，重复准备保留账号和聊天记录，退出桌宠会回收自己启动的中继。独立适配器路线直接使用「独立适配器接入」。

使用 `wss://IP:端口/desktop` 且服务器采用自签名证书或私有 CA 时，先填写服务器地址，再在地址下方点击「导入」选择 CA 或自签名服务器证书。支持 PEM、CRT、CER、DER 及 PEM 证书链；只分发公钥证书，**不要把服务器私钥复制到客户端**。证书会按 IP / 主机绑定并同时用于 `/desktop` 与 `/account`，客户端仍校验证书有效期和主机名；IP 证书必须在 Subject Alternative Name 中包含对应 IP。

共享实例的人格、模型、插件和部分全局学习数据由管理员统一维护。独立会话不代表完整的数据租户隔离；长期记忆共享与人物画像范围详见部署指南。

## 原插件接入（兼容）

以下为原网关插件路线，需要单独克隆上游 `MaiBot/` 与 `MaiBot/plugins/desktop_pet_adapter`。原网关插件是独立私有仓库，需要仓库访问权限或部署方提供的插件文件；公开 Release 中的 `MaiBot-Desktop-Message-Adapter` ZIP 是独立适配器，不能代替它。内核源码保持不变，插件保留独立 Git 历史。要求 MaiBot **1.3.5–1.3.x**、SDK **2.10+ / <3**、Python **3.12+**；使用上面的独立适配器时无需完成本节。

1. 安装 Python 3.12+ 与 uv，在 MaiBot 目录执行 `uv sync`。
2. 执行 `uv run bot.py`，在终端阅读并确认 MaiBot 的协议与隐私条款，完成配置生成。
3. 按 MaiBot 指引，在它的管理界面配置对话与视觉模型的服务地址、模型名和 API Key。
4. 将原网关插件 ZIP 解压到 `MaiBot/plugins`，或克隆原插件源码。在 MaiBot 目录执行下列命令安装公开依赖：

   ```powershell
   uv pip install --python .venv/Scripts/python.exe -r plugins/desktop_pet_adapter/requirements.txt
   ```

5. 使用原本机适配器接入时，展开桌宠「连接与账号」→「旧版接入」→「本机适配器接入」。端口可留空自动分配，也可手动填写；点击「导出插件配置并开启接入」，保存为 `MaiBot/plugins/desktop_pet_adapter/config.toml`，其中包含实际端口和自动生成的独立令牌。已有安装会继续使用之前保存的端口。
6. 启动或重载 MaiBot，桌宠显示 **“协议 v1 · 会话已确认”** 后即可聊天。插件自动注册账号路由；如内核配置了适配器名单策略，需要允许该私聊。MaiBot 管理界面的默认地址是 `http://127.0.0.1:8001`。

桌宠监听本机回环地址，插件主动连接，支持新旧插件实例并存的重载过程。插件令牌独立于 WebUI、模型服务和旧消息服务令牌。配置文件含凭证，请妥善保存；桌宠本地使用系统加密保存令牌。

桌宠默认使用固定的 `desktop_owner` 身份；插件通过 `ctx.chat.open_session` 获取真实私聊流。保持平台、机器人账号、用户 ID 与空作用域可延续原有归属。远程内核、多套桌宠、消息回执及协议版本见原网关插件仓库内的 `README.md` 与本仓库的[维护指南](docs/maintenance.md)。

从 0.1.0 升级时，会先备份 `state.v1.backup.json`，保留历史、角色、语音配置和身份，停用旧自动连接。到本页面导出插件配置完成迁移；旧内核令牌不会复用，也不会继续走旧协议。无需再为桌宠添加 `bot.platforms` 条目，已有其他平台配置照常保留。

MaiBot 由部署方独立启动和管理，桌宠客户端只负责连接、登录和日常使用，不提供 MaiBot 启动、停止或管理后台配置。需要本机测试时展开相应入口；它仅管理桌宠中继，不管理 MaiBot 进程。

## 角色资源

在「角色衣橱」点击「导入角色」，程序将需要的资源复制到应用数据目录。

- 图片：PNG / JPG / WebP / GIF，可直接选文件。
- PNGTuber：同目录准备 `idle.png`、`talking.png` 与以下 JSON，选择 JSON 导入。

  ```json
  { "name": "我的麦麦", "idle": "idle.png", "talking": "talking.png" }
  ```

- Live2D：支持 Cubism 2 的 `.model.json` + `.moc`，以及 Cubism 3 / 4 / 5 的 `.model3.json` + `.moc3`。选择入口文件，或点击「导入模型文件夹」，自动复制贴图、动作、表情、物理、姿势与动作音频；文件夹中存在多个入口时会提示选择具体文件。ZIP 请先解压；`.cmo3` / `.can3` 编辑器工程需先导出运行时模型。

  首次导入会自动准备对应运行库：新版从 [Live2D 官方](https://cubism.live2d.com/sdk-web/cubismcore/live2dcubismcore.min.js) 下载 Core；旧版使用经过固定 SHA-256 校验的 N.E.K.O 归档。也可在衣橱中提前下载，或从本地导入通过校验的 `live2dcubismcore.min.js` / `live2d.min.js`。两套运行库独立缓存，下载一次后可离线复用；更新新版 Core 时，正在显示的新模型会重新加载。模型旁的任意脚本不会执行，运行库不打入安装包，使用遵循其文件中的许可。

  渲染器采用 N.E.K.O 使用的同一维护分支，并适配复杂遮罩、自定义口型和眼睛参数。已实测 Shizuku、Haru、Mao 与洛天依「翡翠石」，范围与版本边界见 [Live2D 兼容性说明](docs/live2d-compatibility.md)。

- VRM / GLB：选择包含完整资源的单个 `.vrm` / `.glb` 文件。
- MMD：将 `.pmx` / `.pmd` 及贴图放在独立文件夹中，选择模型文件；导入同文件夹内的模型资源。当前提供静态模型、呼吸与常见表情 / 口型映射，未包含 MMD 物理或 VMD 动作时间线。

模型不能引用导入目录外的文件或远程 URL，单次导入上限 512 MB。程序不下载或分发角色模型。

## 声音与设备

系统朗读无需 API，声音取决于操作系统已安装的语音包。

录音转写与 API 朗读使用「声音与感知」中配置的兼容服务：`POST /audio/transcriptions`、`POST /audio/speech`，会保留 Base URL 中的 `/v1` 等前缀。本地兼容服务可以不填 API Key。先保存配置，再使用录音测试；测试转写不会自动发消息。

连续语音只在桌宠窗口运行，点击连续语音按钮或对应开关开始；每段最长 45 秒。等待回复时继续聆听；播报期间持续开口可停止当前本机声音，再录制下一句，短促噪声不会触发打断。隐藏桌宠、断线或开启专注会关闭连续语音并释放麦克风。停止本机声音不会取消 MaiBot 的生成，回复仍由内核决定。

Live2D、VRM / MMD、PNGTuber 与默认角色的口型跟随正在播放的实际音频响度，停顿时闭嘴；主窗口和桌宠同步，角色衣橱预览保持静止。系统朗读无法读取波形时保留基础口型动画。界面分别显示录音、转写、发送、等待和播放状态；发送后等待提示约 15 秒恢复空闲，MaiBot 选择不回复时不会显示失败，也不会把任意回复都判定为开心。

恢复组合键召回桌宠与控制面板，并立即恢复鼠标交互，不等待设置写盘。主窗口关闭后保留托盘；托盘菜单「退出 Mai」才结束应用。

桌宠问候气泡显示 5 秒后自动收起；新的即时回复按显示长度保留 8～15 秒。历史补载、状态刷新和语音播放不会延长时间或反复弹出旧句，气泡收起后语音继续播放。点击角色可重新查看最近回复，手动关闭后等待下一条新回复再弹出；完整内容保留在聊天记录中。

使用 API 朗读时，可在「声音设置」调整「预缓冲文字条数」：默认提前准备后续 2 条文字回复的开头，支持 0～5 条，0 关闭跨消息预缓冲。播放保持消息到达顺序，MaiBot 原始语音在原位置播放，不会额外合成同一条消息的文字；长回复内部的预合成仍由「长回复连续播放」独立控制。停止、专注或切换会话会清理待播队列，切换音色后后续文字使用新音色；已提交的合成请求仍可能产生费用。

预合成发生普通临时服务错误时，轮到对应消息或分段会重新合成一次，后文等待它完成。限流统一按下述队列策略恢复，达到重试上限或遇到认证、权限、余额错误会直接提示，不叠加前台重试。停止或取消后，迟到结果不会触发重试或恢复旧朗读。

MiMo 朗读、预缓冲与试听共用主进程请求队列，按单请求和至少 700 毫秒的起始间隔准备音频，这是客户端的保守策略。429 会让同一模型的队列共同冷却，并尊重服务返回的 `Retry-After`；单次合成最多尝试 3 次，较长等待会显示受限提示，不提前重发。429 可能表示请求限流，也可能表示账户额度限制；401、403、402 分别提示认证、权限与余额问题，不自动重试。取消操作会移除尚未发送的任务，并中止正在等待的请求。

## 从源码运行与打包

以下命令用于从源码开发、构建：

Node.js **22.12+**（开发环境已使用 Node.js 24 验证）。

```powershell
git clone https://github.com/pan-ice/desktop_mai.git
cd desktop_mai
npm ci
npm run dev
```

`npm run dev` 和 `npm run dev:web` 每次启动都由系统动态分配本机开发端口，终端显示实际地址，桌宠窗口和热更新自动跟随；同一进程内的开发服务重启保留当前端口。关闭开发应用后命令随之退出。启动脚本会清理影响 Electron 启动的遗留环境变量。

也可以双击 `启动桌宠.cmd`，或直接运行：

```powershell
npm start
```

`npm start` 会检查源码与完整的主进程、preload、页面及资源产物；缺失、过期或被开发模式覆盖时会先重新构建。可单独运行 `npm run build` 提前构建。正式发行包使用自身页面，忽略开发页面地址。

Windows 安装版和便携版构建：

```powershell
npm run dist:win
```

生成安装版 `release/Mai-Desktop-Pet-0.4.11-win-x64-Setup.exe`、便携版 `release/Mai-Desktop-Pet-0.4.11-win-x64.exe` 和独立的 `MaiBot-Desktop-Message-Adapter-0.1.1.zip`。已构建页面时，可用 `node scripts/package-win.mjs --installer` 或 `--portable` 只生成对应版本。正式桌宠直接加载包内页面，不启动开发网页服务，也无需安装 Node.js；新适配器解压到独立目录，以 Python 进程运行。发行包不包含内核、凭证或角色模型。原网关插件可在获取其源码后使用 `npm run dist:plugin-adapter` 单独打包。

macOS 在 Mac 上执行 `npm run dist:mac`，按当前 Node.js 架构生成 `release/Mai-Desktop-Pet-0.4.11-mac-arm64.dmg` / `mac-x64.dmg` 及同名 ZIP。GitHub Actions 的“桌宠发行包”同时构建 Windows x64、Mac Intel 和 Apple Silicon，全部验收通过后发布 Release；维护方式见[维护指南](docs/maintenance.md#发布)。

## 数据与开发

默认数据目录：`%APPDATA%\Mai Desktop Pet`，可在「偏好设置」中打开。开发测试使用 `MAI_USER_DATA` 指定隔离目录。

```text
electron/        Electron 主进程、协议桥接、本地数据与设备操作
adapter/         独立 Python 适配器、官方消息协议转换、配置与锁文件
shared/          共享类型、配置默认值与 IPC 输入校验
src/             React 控制面板、桌宠、语音与模型渲染器
resources/       应用图标
tests/           协议、重连、模型导入、媒体存储、陪伴策略测试
scripts/         插件打包、桌面与实际 SDK 联调、进程生命周期验收
MaiBot/          独立上游内核仓库
  plugins/desktop_pet_adapter/   独立适配器仓库，包含锁文件、协议、测试和 CI
references/      开发参考仓库，不进入应用打包
```

插件开发环境可独立初始化；跨语言与桌面测试使用它的解释器：

```powershell
cd MaiBot/plugins/desktop_pet_adapter
uv sync --locked
cd ../../..
# 可通过 MAI_PYTHON 指定其他已安装 SDK 和 websockets 的解释器。
npm run test:plugin
npm run test:adapter
```

桌面测试使用本地测试服务、生成的几何模型与虚拟音视频设备，结束时关闭所有测试应用和服务；不会使用你的模型 Key 或向在线模型发送请求。

`test:runtime` 对开发页面、构建页面和实际解包 EXE 使用同一组功能验收；`--mode=packaged` 默认使用 `release/win-unpacked/Mai 桌面伙伴.exe`。增加 `--live2d` 可复验三代模型的双窗口渲染和重启离线复用，需要先通过 `test:live2d-compat` 准备本机测试缓存；此选项本身不下载模型或运行库。

长期维护的模块约定、版本策略和发布检查见 [维护指南](docs/maintenance.md)。公开 Release 提供独立适配器源码 ZIP；原网关插件仍需单独获取到上述路径，尚未发布到插件市场。
